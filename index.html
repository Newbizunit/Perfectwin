A few practical answers

Clarity before
the conversation.

Is PerfecTwin an S/4HANA data-migration reconciliation tool?

Not based on the supplied documentation. The strongest supported positioning is SAP business-process and regression testing around a transformation. The manual documents scenario execution, test data, SQL nodes, result evidence, and summary comparison between tagged runs; it does not establish automated field-by-field source-to-target reconciliation for an entire migration. Any separate reconciliation capability should be confirmed and documented before it is marketed.

How should we evaluate PerfecTwin against a broad platform such as Tricentis Tosca?

Compare the products against your actual priority workflows, interfaces, data approach, authoring and maintenance effort, evidence requirements, deployment model, and total implementation scope. Broad platforms may offer capabilities outside PerfecTwin's documented scope. PerfecTwin's most credible evaluation angle is the relevance of its real-transaction-based SAP process testing and execution evidence for your transformation—not an unsupported claim that it is universally superior.

Which SAP and web interfaces are covered here?

The supplied ERP Edition manual documents recording targets for SAP WebGUI, SAP Fiori (UI5), and Web UI. The v26.9 release adds SAP GUI tree actions captured within a WebGUI unit. This concept does not imply native desktop SAP GUI support, universal SAP version compatibility, or coverage of every interface. Confirm your specific environment with the product team.

Is AI Recording included as a standard feature?

The v26.8 notes identify AI Recording as a Lab feature. It appears only when enabled in Lab and requires the user to register an Anthropic or OpenAI API key in AI Management. AI Recording operates the SAP screen from an instruction and records the interaction; it is not evidence that the entire testing lifecycle is autonomous. Confirm availability and suitability for your deployment.

Can we use our own test data?

The manual documents test data and source data management with Excel and database-backed workflows. The v26.8 update adds database source-data download to Excel, with an edit-and-upload round trip. Your team still needs to prepare suitable test data and confirm access, privacy, and environment requirements.

How does result comparison work?

Compare two completed or failed runs of the same scenario with different tags. The documented comparison shows summary metrics including pass rate, duration, and failure counts. It should not be described as automatic field-by-field reconciliation between two production systems.

What should we bring to a demo?

Start with a representative workflow, the SAP and web interfaces it touches, your change initiative, and how you currently evaluate results. Ask the product team to confirm deployment options, version compatibility, licensing, data handling, support, and any required integrations. Those commercial and technical details are not established by the documents used for this concept.

About this concept: source documents, claim boundaries, and items to confirm before publication

Scope: PerfecTwin ERP Edition only. The 372-page v26.7 User Manual and the 14-page v26.8-v26.9 Release Notes are the product sources. The release notes take precedence where behavior has changed. This is a marketing interpretation of documented capabilities, not independent product verification or confirmation of commercial availability.

  • Record and reuse: Manual pp. 4-14 and recording target sections beginning pp. 15, 34, and 98. Visual scenarios and templates: pp. 244-303. Scheduled runs: pp. 304-312.
  • Data and governance: Manual pp. 313-339 for data management; pp. 350-357 for user and role administration. No compliance certification or security guarantee is inferred.
  • Results: Manual pp. 340-349. Tagged-run comparison is a summary-metric comparison, not a claim of transaction-level system reconciliation.
  • AI: Release Notes pp. 2-4. AI Recording is a Lab feature with BYOK requirements. Do not market it as generally available or fully autonomous testing.
  • New features: Release Notes pp. 4-7 for Web UI, Header-Loop, data, and file improvements; pp. 9-14 for dashboards, GUI Tree, and result storage and cleanup changes.
  • Illustrations: All interface visuals, test values, workflow names, and the sample schedule are illustrative. They are not customer evidence, measured outcomes, or exact reproductions of the product UI.
  • Deliberately omitted: Unverified ROI, speed and coverage statistics, customer endorsements, certifications, U.S. customer or support claims, native desktop GUI claims, pricing, and guarantees of SAP version or migration compatibility.
  • S/4HANA positioning: This concept frames documented testing capabilities around an S/4HANA transformation use case. It does not claim that PerfecTwin performs the technical conversion, remediates custom code, replaces UAT, governs cutover, or provides full source-to-target data reconciliation.
  • Competitive positioning: The conventional-versus-PerfecTwin section is a messaging framework, not a Tosca feature comparison or benchmark. Validate any named competitive claims with legal, product, and sales leadership before publication.
  • Before publishing: Obtain HQ and U.S. sales approval of claims and feature availability. Confirm supported SAP versions, deployment and data-handling terms, licensing, support, integration scope, brand assets, and approved case studies. Review AI provider data handling and costs before promotion.
  • Demo links: Buttons navigate to the existing PerfecTwin contact page. This standalone prototype has no lead-capture backend, tracking, remote fonts, or third-party scripts.
